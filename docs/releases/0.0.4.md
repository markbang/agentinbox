nsh-mail is now **AgentInbox**, and it brings a second inbox: every notification your work produces — mail, webhooks, Gotify, ntfy — in one feed that you and an agent read the same way.

## What's in 0.0.4

### Added

- Cloud mode's notification inbox now talks to the server: the feed, its sources and the API keys are the server's own (unread counts per source, search, paging, mark read, archive), and new notifications arrive over the server's stream — they appear in the feed and as system notifications without a reload or a pull to refresh. The same key an agent uses reads the same inbox.
- Local mode's feed is the mail on the device: every account's mail is in All notifications, opening one marks the message read and archiving one moves the message to Archive, so the app and an agent agree. Source settings there are the mail accounts; the Sources and API keys pages say that webhooks, ingest URLs and agent keys are kept by a server, instead of offering buttons that cannot work.
- API keys for agents, and the API they open: create a key in Settings → API keys (`nb_…`, name, read or write, chosen sources, expiry) and it is shown once — only its hash is kept, and the app's list shows just its first characters, when it was last used and whether it was revoked. With it an agent reads the notification feed (`GET /v1/feed`, with unread, source, since, full-text search and paging), reads one notification, marks it read and archives it; every request is limited to that key's sources, and marking read or archiving needs the write scope.
- Live notifications for agents: `GET /v1/stream` (SSE) pushes new notifications, reads and archives, resumes from `Last-Event-ID`, filters by source and keeps itself alive every 15 s; `?format=ws` does the same over a WebSocket. The MCP tools are served at `/mcp` with the same key, so Claude Code, Codex or Cursor can point at the server itself instead of the standalone binary.
- Archiving a mail notification now moves the mail to Archive, and mail that is already in Archive is shown as handled instead of as a new notification.
- Notification inbox, foundations: mail now appears in one unified feed next to every other source, and a server API manages those sources (create, rename, pause, delete), each with an ingest URL whose token is shown once and can be rotated.
- Notification ingestion: one webhook URL per source accepts JSON or form posts with GitHub, GitLab, Sentry, Grafana and Uptime Kuma presets (or your own field mapping), checks an optional `X-Hub-Signature-256`, and drops a sender's retries by their own id. Gotify's `POST /message` and ntfy's `POST /topic` work by changing the host, ntfy's `GET /topic/json` streams live, and HTML is sanitized like mail (remote images removed).
- An **All notifications** feed beside the mail inboxes: every source's messages in one list, grouped by day, with the source's icon and colour, a dot for high priority, tags, a count per source and search across everything. Opening one marks it read; swipe it away or use its actions to archive; a mail notification opens in Mail. On phones it is a Notifications tab, on the desktop and the web the first rail destination.
- **Sources** in Settings: add a webhook, Gotify or ntfy source, copy its ingest URL once, send a test message, pause it, show its URL again (which replaces it) or delete it.
- **API keys** in Settings, for agents that read the feed (REST, the event stream, MCP): create one with read or read-and-write scope, every source or a few, and an expiry; its token is shown once; revoke it and the agent stops at once.
- **Per source and priority** notification rules: each source's high, normal and low priority notifications can show on your devices, sit in the feed only, or be dropped.
- An MCP server for agents (`agentinbox-mcp`): list unread notifications, search across every source, read one in full, mark it read and list sources, over stdio or HTTP with an API key. Config blocks for Claude Code, Codex and Cursor are in `crates/mcp/README.md`.
- Signatures, one per account (Settings → the account's menu → Signature), with **bold**, *italic* and links. Added to new messages and to replies and forwards (each can be turned off), above the quoted message as Gmail does, and sent as plain text and HTML. Changing From in the composer swaps it, unless you edited it. Kept on the device in local mode, on the server in cloud mode.

### Improved

- **AgentInbox**, previously nsh-mail: the app, the server, the Docker images and every download now carry the new name. It is an update, not a second app — the Android package id (`top.bangwu.nshmail`) and the signing key are unchanged, so a 0.0.2 APK updates in place, keeps its accounts, settings and mail, and only the launcher label becomes AgentInbox (nothing to uninstall). The `nshmail://` sign-in links, the `nshmail.` storage keys and the `NSHMAIL_*` environment variables keep working, and the old `ghcr.io/markbang/nsh-mail*` images stay published for one release cycle so a deployment can roll back. Linux users replace the old folder and launcher entry (see [docs/linux.md](../linux.md)); Windows users uninstall the old nsh-mail once.
- A notification changes only the notification feed: a change with no mail account behind it (a new webhook, the stream reconnecting) no longer re-reads the accounts and the mail counts too.
- Keyboard and screen readers. Every control is a Tab stop with Material's focus ring and presses with Return or Space, and `?` — or Settings → Help — lists the shortcuts, each key as your platform names it. Screen readers hear the snackbar as an alert for failures and a status for confirmations, the mailbox, search, sidebar and toolbar names, and rows as unread, sender, count, subject and date.
- Large mailboxes: the first sync now arrives in pages, so the inbox opens while the rest is still coming, and its progress shows in the mailbox rail. If it stops midway, the next sync continues from where it stopped instead of starting over. A new "load older mail" path pages further back as you scroll to the end of a folder, and that older mail is searchable once loaded.
- The list stays smooth in a large mailbox. Scrolling and loading older mail recycle the rows instead of rendering the whole mailbox, and a sync now costs the same however far down you are: new mail appears in the first page and the rows below keep their place (before, a sync while scrolled deep reloaded and redrew everything, one 350 ms stall on the web with 10,000 messages loaded — now 50 ms). Paging past 500 conversations no longer cuts the list back to the first page. A conversation of 200 messages opens on its first and last few; **More** reveals 25 at a time, and **Show less** folds them back.
- Empty, loading and failure states across the app. An empty folder says which one it is and offers New message where that helps; a search shows a hint before you type, a loading indicator while it runs, and the reason with Try again if it fails. A mailbox that won't load, a message that won't open and a failed sync all say what to do next, in the list, in the reader and in a banner with a retry. An IMAP sign-in the server refuses now explains app passwords, with a link for the provider.

### Fixed

- Settings' About line showed a version number that never changed; it now shows the one the build reports.
